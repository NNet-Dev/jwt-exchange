# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- **Optional replay allowance (`ALLOW_REPLAY`)**: When enabled via `ALLOW_REPLAY=true`, the same JWT `jti` may be exchanged twice — once with groups and once without. The `used_jti` table now uses a composite primary key `(jti, has_groups)` to track this. Default remains `false` (strict: any prior use blocks all subsequent exchanges). Includes integration tests for both strict and replay modes.

### Changed

- **Product-agnostic environment variable names**: `OKTA_ISSUER_URI` → `INBOUND_ISSUER_URI`, `OKTA_AUDIENCE_VALIDATION` → `INBOUND_AUDIENCE_VALIDATION`, `OKTA_EXPECTED_AUDIENCE` → `INBOUND_EXPECTED_AUDIENCE`. The `OktaUnavailable` error type and `okta_unavailable` error code are now `IdPUnavailable` / `idp_unavailable`. All references to "Okta" in error messages, log output, and documentation have been replaced with generic "IdP" or "inbound" terminology.

## [1.0.1] — 2026-05-21

### Fixed

- **Replay detection now records inbound claims**: Previously, replay-detected audit logs showed `null` for `inbound_sub`, `inbound_iss`, `inbound_aud`, and `token_jti`. The `ReplayDetected` error variant now carries the extracted claims from the validated token so the audit log shows exactly *which* user and token is being replayed.
- **Validation field corrected for replays**: Audit records for replayed tokens previously showed `"validation": "token has already been used..."`. Since the replay check runs *after* successful signature/issuer/expiry validation, the validation field now correctly shows `"success"` — the token itself was valid, it was just already consumed. The error details remain in `error_detail`.

### Changed

- `ServiceError::ReplayDetected` now carries `inbound_sub`, `inbound_iss`, `inbound_aud`, and `replay_id` fields instead of being a unit variant.

## [1.0.0] — 2026-05-17

Initial release. Full security-hardened JWT exchange service.

### Security Fixes

- **Replay protection now functional**: Added `used_jti` table with `UNIQUE(jti)` constraint to both the migration file and inline pool creation. Tokens are now atomically checked before exchange.
- **JTI-less token handling**: Tokens without a `jti` claim are no longer silently bypassing replay protection. A SHA-256 hash of the raw token is used as a secondary replay identifier.
- **Audience validation enabled by default**: Inbound tokens now validate their `aud` claim against `INBOUND_EXPECTED_AUDIENCE`. Startup fails if validation is enabled but the audience is not configured.
- **RSA key permissions enforced**: Private key files are created with `0600` permissions and checked/fixed on startup.
- **Splunk HEC TLS strict by default**: `danger_accept_invalid_certs(true)` removed. TLS verification can be disabled via `SPLUNK_HEC_SKIP_TLS_VERIFY=true` (default: `false`).
- **Splunk audit events no longer dropped on failure**: Retries with exponential backoff (3 attempts). Events lost after all retries are logged at ERROR level.
- **No raw tokens in Splunk events**: JTI values truncated to first 8 hex chars; full tokens never logged to SIEM.
- **JWKS force-refresh rate-limited**: 60-second cooldown between force-refresh attempts. Circuit-breaker trips after 5 consecutive failures.
- **X-Forwarded-For validated**: First non-empty IP extracted from comma-separated XFF header; empty values skipped.
- **Request ID in all responses**: Middleware injects `X-Request-Id` header into every response, including error responses generated by actix-web.

### Hardening

- **Input size limits**: `MAX_TOKEN_SIZE` (default: 10KB), `MAX_GROUPS_COUNT` (default: 50), `MAX_GROUP_NAME_LENGTH` (default: 256). Exceeding limits returns 400.
- **SQLite WAL mode enabled**: Database connections use `journal_mode=WAL` for better concurrency. Graceful shutdown performs `PRAGMA wal_checkpoint(TRUNCATE)`.
- **Docker runs as non-root**: Container uses `distroless/static-debian12:nonroot` base image.
- **Docker DB path persistable**: Database defaults to `/data/jwt-exchange.db` (mountable volume) instead of `/tmp`.
- **Health endpoint simplified**: Returns status + uptime + component checks without leaking internal details.
- **`.dockerignore` added**: Prevents build artifacts, `.env`, and `.git` from entering the image.

### Dependencies

- Added `sha2` (SHA-256 for token hashing), `hex` (hex encoding), `futures` (middleware async support).

### Breaking Changes

- `INBOUND_AUDIENCE_VALIDATION` now defaults to `true`. Existing deployments must set `INBOUND_EXPECTED_AUDIENCE` or explicitly disable validation.
- `SPLUNK_HEC_SKIP_TLS_VERIFY` now defaults to `false`. Deployments with self-signed Splunk certificates must explicitly set `SPLUNK_HEC_SKIP_TLS_VERIFY=true`.
- Docker image now runs as UID 65532 (`nonroot`) instead of root. Any volume mounts must be writable by this user.
- Docker database path changed from `/tmp/jwt-exchange/audit.db` to `/data/jwt-exchange.db`.

## RCA-001: Build-Orchestrator Foundation Sync Introduced 9 Compile Errors

- **Severity:** HIGH
- **Root cause:** Missing compile-validation gate in build-orchestrator pipeline; agent wrote 15 commits without running `cargo check`, introducing actix-web v4 API mismatches, Result destructuring bugs, and broken sqlx compile-time macros.
- **Corrective:** Rewrote `middleware.rs` for actix-web v4, fixed `jwks.rs` match logic, generated `.sqlx/` offline cache.
- **Preventive:** Add contract rule requiring `cargo check` before each commit; add CI compilation gate.
